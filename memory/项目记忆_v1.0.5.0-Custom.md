## 3. 未提交但已完成的功能（当前工作区，22 个文件改动）

### 3.1 移除拖拽蓝色指示（用户要求"完全移除"）

- `Slot::DrawDropIndicator/WithStyle` 整体删除（slot.h/slot.cpp）——蓝色空位框与插入竖/横条
- `WidgetContainer::DrawDropPreview` 删除；集合组/文件组只保留橙色组级框
- `DockContainer::DrawInsertionPreview` 删除，落点预览只保留 Handoff 绿框
- 桌面落点蓝色方框全部移除（`DrawDesktopDropPreviewList` 函数已删），**红色占用提示框保留**
- 桌面左右边缘蓝色竖线移除（拖到边缘停留翻页和悬停提示胶囊保留）

### 3.2 单图标插入判定（对齐 Win11 原生）

- 位置：`app_drop_preview.cpp` 单图标分支
- 用 `dragSession_.ResolveDraggedBounds`（虚影真实屏幕矩形）取**图标视觉中心** → `CellFromPoint` 最近格心吸附
- 命中格被占用时**按占用者读取方向中线分前后**：中心在中线之后 → 插到占用者之后一格（`nextSlot` 后移）；之前 → 占其格由 `ResolveDesktopInsertionCollisions` 顺延
- 注意：桌面 grid 的 slot = column\*rows + row（列为主序，同列先向下）

### 3.3 多选跨页顺序修复（核心）

- `MigrateSelectedItemsToLastMonitorPage`（app_grid_drag.cpp）改为**整组保形迁移**：复用落位同一套规划 `BuildSelectedMove(groupAnchor)` → 失败则 `BuildNearestSelectedMove`；整组放不下则不迁移
- **教训**：旧实现（含 v1.0.3-Custom）逐项放置 + 冲突时按 `items_` 名字序从 (0,0) 行优先扫描，目标页有任何占用就会把整组按名字序塞到页面开头——这是跨页乱序的根因，已用诊断日志实锤
- 大图标（largeIcon）拖拽仍是"翻页仅预览不迁移"路径（1.0.5 新增，保留）

### 3.4 拖拽流畅度优化

- `app_pointer_move.cpp` 拖拽分支：采样点未变化时早退（高报点率鼠标的重复 WM_MOUSEMOVE 不再走完整管线）
- `app_drag_lifecycle.cpp` `PresentPointerInteractionFrame`：普通图标拖拽在桌面目标上按 Handoff 框新旧区域**脏区提交**，`StaticSceneRevision` 变化（翻页/布局迁移）时强制整帧一次（修复了圆点翻页不实时的回归）
- 成员：`presentedDragHandoffBounds_`、`presentedDragDesktopScoped_`、`presentedDragStaticSceneRevision_`（app.h）

### 3.6 P0 流畅度修复（2026-09-20，编译待验证）

排查报告结论（三路探查，file:line 已核实）记于当日会话；已实施三处：

- **组件 Resize 每采样点整窗失效 → 新旧 bounds 并集脏区**（app*pointer_move.cpp 约 759-770）。
  依据：组件像素在独立 DComp 子表面（根场景不画组件本体），桌面目标无落点占位框。
  契约测试 dock_and_window_rules_tests 8611 本就要求 resize 热路径不得含
  `InvalidateRect(hwnd*, nullptr`——改前该处违反此契约（预先存在的红灯），现已对齐。
- **纯桌面目标组件拖拽/缩放跳过整帧前景重呈现**（app*drag_lifecycle.cpp widget 分支）。
  蓝框移除后桌面目标无前景绘制内容；仅当本次或上次反馈含 Dock 高亮/组橙框/边缘提示
  时才 `PresentDesktopForegroundComposition(client)`。跳过分支仍置
  `widgetInteractionPresented=true` 保持 presentedWidgetDragFeedback* 记录时序（:355）。
- **图标加载完成按项/按组件框失效**（app_desktop_reload.cpp OnIconLoaded 桌面项 +
  文件夹条目两处）：`item.bounds` / `widget.bounds` +4px 脏区，bounds 为空回退整窗。
  消除启动期 N 个图标 = N 次全屏重绘的放大效应。

### 3.8 溢出页 1x1 尺寸损坏修复（2026-09-23，未提交、待编译验证）

**症状**：重启后多文件叠在同一格渲染（截图1 文件名互相叠压）；刷新后页面只剩一个占满整页的巨大图标，该页其余文件全部挤回第一页（截图2）。

**根因链**（三步，均已用 `.build\Release\data\backups\1.json`（好：page2/3=20x8，13+20 项）与 `2026-09-21 16-08-34（恢复前备份）.json`（坏：1x1）对比实锤）：

1. **启动误判**：启动顺序为 LoadLayoutSlots → `UpdateLayoutWorkArea`（内部 `ApplyPageMapping` → `PruneEmptyOverflowPages`，app*page_grid.cpp:1447）→ `ReloadItems`。清理运行时 `items*` 尚未从 shell 枚举恢复，`PageHasContent`（原 app*page_grid.cpp:1125）只查运行时 items*/widgets* → "只含文件、没有组件"的溢出页被判空 → 从 savedPageIds* 清理并**擦除 savedPageColumns*/savedPageRows***。
2. **保存造假**：`SaveLayoutSlots` 中 `RememberSavedPageId(item.gridCell.pageId)`（app*layout.cpp:834，现约 :857）把 items 引用的死页 id 重新加回 savedPageIds*（无尺寸）；pages 写盘对不在 gridPages\_ 且无尺寸记录的页写 `max(1,0)=1` → **1x1 持久化**。
3. **刷新挤爆**：1x1 页只装 1 个图标（名字序第一个，占整页=巨大图标），其余溢出回第一页并固化。第一张截图的叠压 = 页面被 clamp 到 (0,0) 1x1 后多项重叠渲染。

**修复**（2 处，均已实施，用户手动编译验证）：

- `PageHasContent`（app*page_grid.cpp:1125）：运行时视图无内容时回退查 `layoutRecords*`（排除 widgets\_ itemKeys 收录的 key），文件未枚举完成时不再误删页面。
- `SaveLayoutSlots`（app*layout.cpp 约行 859，gridPages* 尺寸同步循环之后）：写盘前给缺尺寸的待写页面回退末屏显示器网格（与溢出页创建路径一致），保证 1x1 占位尺寸永不被持久化。

**注意**：

- 用户初始怀疑的 OnIconLoaded 全屏失效（app_desktop_reload.cpp:1121/1175）是性能问题，2026-09-20 已改按项脏区失效（见 3.6），与本 bug 无关。
- 已损坏的布局数据不会自愈：用户选择手动修复（设置→页面布局把 page2/3 改回 20x8，文件拖回；原始摆放可对照 `backups\1.json`）。
- 提交需用户批准。

## 5. 关键事实备忘

- `items_` 数组顺序是**名字序**（shell 枚举），与视觉排列无关；视觉顺序以 `gridCell`/`slot` 为准
- 页面可逐页设置网格尺寸（savedPageColumns*/savedPageRows*），跨页时行列数可能不同
- 翻页圆点悬停翻页：`UpdateDragPageNavigation`（app_drag_target_update.cpp）内圆点命中 + 边缘热区停留 500ms 两条路径
- `f29a882` 历史教训：指针反馈必须同步提交，不能走 UiAnimationScheduler（会晚一帧）
- 桌面宿主窗口无法用 computer-use 自动化验证，视觉/交互一律用户实机验证
- git 提交必须用户明确批准；提交信息中英双语（AGENTS.md）
